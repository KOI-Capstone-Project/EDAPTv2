Before EDAPT · §1.3 Problem Statement

Academic risk was found by accident, not by design

  • 01 Assessment & attendance data sat in CSV dumps too large to read by hand
  • 02 Risk was flagged only after a staff member happened to notice
  • 03 No standard way to compare subjects, cohorts, or terms
  • 04 Manual aggregation carried a real risk of human error
  • 05 Nothing predicted an outcome before it had already happened
  • 06 No channel to act on a flagged student directly
The aim · §1.4

Build a system KOI can trust to say why — not just who's at risk.

Descriptive and predictive analytics, evaluated to a technically and ethically defensible standard — not a black box, and not a single reported accuracy figure.

What the system must do · §2.1 Functional Requirements

Nine capabilities, from login to audit trail

  • AuthenticationRole-based access control at every endpoint.
  • Data ingestionAccepts institutional CSV extracts, validating column structure on the way in.
  • Descriptive analysisInstitution-wide analytics, filterable by year, subject and lecturer.
  • Predictive analysisA pass-probability for a given student and subject, from data confirmed available at prediction time.
  • Model governanceEvery trained model is kept on record; nothing reaches production without human-authorised promotion.
  • Intervention trackingA record of action taken against a flagged student — contact made, meeting scheduled, referral made.
  • AI-assisted functionalityGemini, Anthropic or OpenAI, switchable at runtime with no redeploy.
  • Outgoing communicationOne or more SMTP servers, credentials encrypted at rest.
  • AuditabilityA permanent trail of key administrative activity, available to authorised roles.
How it must behave · §2.2 Non-Functional Requirements

Ten quality attributes, each with a stated target

  • PerformanceA normal-sized institutional extract loads the dashboard within 3 seconds.
  • Model performanceFail-class precision/recall as the real criteria; ≥75% accuracy only as a sanity check.
  • ReliabilityFails gracefully on missing data — never a confident, wrong answer.
  • SecurityJWT-authenticated sessions and role-based access on every sensitive endpoint.
  • PrivacyMasked identifiers throughout — no claim of full anonymisation the system can't prove.
  • AuditabilityEvery major admin action recorded and traceable.
  • UsabilityUsable by academic staff with no SQL or data-analysis background.
  • MaintainabilityModular, documented, with an automated regression suite run on every change.
  • ScalabilityModular architecture — React, FastAPI, PostgreSQL, Docker — extendable with no redesign.
  • PortabilityDeployable from source via Docker Compose, dev and prod alike.
Under the hood · §3 System Architecture

React 18 + Recharts

Role-scoped SPA; navigation guards for UX, never the security boundary.

FastAPI · Gunicorn

Auth, business logic, the ML pipeline, and every external-service call.

Relational store for operations; academic data lives in-memory for speed.

Proven in practice: the AI provider layer went from one hardcoded integration to a runtime-configurable one — with zero changes to the layers on either side.

What's actually in Postgres · §4.4 Database Design

Operations and governance are relational — academic data isn't

Users, predictions, interventions, audit logs, mail servers and AI provider configs live here. Academic source records don't — they're processed through Pandas DataFrames, not maintained as empty relational tables.

Predictive analytics · §5.5.1

Two models, because a term in progress isn't a finished record

Complete-record model — 65,903 finished enrolments, 124 subjectsUsed once a full record exists
Mid-term model — trained on truncated snapshots (illustrative)Rest of term: unknown at prediction time

Feeding partial data to the complete-record model first hit 100% training accuracy — a textbook sign of leakage, not skill. Hence a second model, trained only on what a mid-term snapshot actually contains.

Model performance · §7.4.1

95.40% accuracy isn't the number that matters

Passing students outnumber failing ones — accuracy alone would flatter a model that misses the exact students it exists to find. We report the fail-class metrics instead, each on the same 0–1 scale.

Talking to the outside world · §5.8–5.9

Integrations & the API surface

AI Providers

Gemini, Anthropic, OpenAI

Configured at runtime through one dispatch function — switching providers, models or keys needs no redeploy.

Outgoing Mail

SMTP + templated email

One or more mail servers, credentials encrypted at rest. Templated notifications for password-reset OTPs and connection tests — every send logged as "sent" or "failed," never falsely "delivered."

REST API

FastAPI, self-documenting

Every capability is a versioned endpoint with OpenAPI docs generated automatically — exposed to Head of Technology as the API Console.

Explainability · §5.5.4

Every prediction ships with its reasons — filtered to what a student can act on

Surfaced

Actionable factors

Behaviour the student can actually change — attendance, assessment coverage, submission timing.

Excluded

Structural & demographic factors

Subject difficulty, assessment weighting, age, background — high SHAP weight, zero use to a student.

SHAP contributions are reconstructed against the model's real output as part of the automated test suite — the explanation is checked, not just displayed.

When our own number looked too good · §7.4.1

An earlier model reported 0.8374 recall. We didn't believe it — and we were right not to.

205enrolments had been mislabelled, all fail→pass
5σhow far the resulting recall drop sat from ordinary noise
2.98ppthe real cost of correcting the ground truth

Once corrected and compared fairly, the current model wins on F1 and PR-AUC — on its own merits, not an inflated one.

Open questions we're tracking · §8.4 & §9

Fairness and security, held to the same standard

Fairness — one observation, not a verdict

Students aged 0–20 currently show lower fail-class recall; one building shows an unexplained pass-rate gap. Neither is dismissed, neither is overstated — both wait on more retraining cycles.

Security — tested, not assumed

JWT + bcrypt for sessions, Fernet-encrypted credentials, a scoped audit log. A leaked env-file's credentials were found already dead — verified by testing them, not by hoping.
